# [拉屎冠軍爭霸賽] 會員與戰隊系統 — 產品需求文件 (PRD)

> [!NOTE]
> 本文件專注於「拉屎冠軍爭霸賽」系統中的核心基石：**會員註冊與戰隊資料庫寫入系統**。本模組負責處理使用者個人帳號註冊，並將使用者安全、準確地寫入對應的戰隊關聯資料庫中，為後續的排便紀錄與積分賽打下堅實基礎。

---

## 1. 專案概述

### 背景與動機
現代人常因飲食不正常、缺乏運動與高壓生活，導致排便不順。為了推廣健康生活與腸胃管理，「拉屎冠軍爭霸賽」應運而生！本系統將枯燥的排便紀錄遊戲化，讓使用者以「戰隊（陣營）」為單位進行對抗。
而**會員與戰隊系統**是整個應用程式的入口。使用者透過快速註冊帳號並選擇加入特定的健康戰隊（例如：專注於膳食纖維的「高纖陣營」或專注於水分補充的「多水陣營」），系統後端 Flask 路由將把使用者資訊與對應的戰隊進行關聯寫入 SQLite 資料庫中。這不僅能建立個人身份，更能透過戰隊歸屬感激發用戶的持續記錄動力。

### 目標用戶
- **腸胃亞健康族群**：希望透過記錄改善排便習慣，但容易忘記、需要社群激勵的上班族與大學生。
- **熱愛遊戲化競爭者**：喜歡爭取團隊榮譽、享受排行榜競爭的玩家。

### 核心價值主張
- **極簡入口**：提供友善流暢的註冊與戰隊選擇流程，降低使用者加入門檻。
- **陣營對立機制**：一開始註冊即進行戰隊選擇，建立強烈歸屬感與競爭意識。
- **安全可靠**：採用安全雜湊密碼存儲，並確保戰隊寫入的資料完整性（Database Integrity）。

## 2. 功能需求

本系統的核心功能需求著重於「會員註冊」、「戰隊選擇」以及「Flask 後端路由與資料庫安全寫入」。以下列出主要功能及其對應的使用者故事 (User Stories)：

### F-01 個人帳號註冊 (Account Registration)
- **功能描述**：新用戶填寫用戶名、密碼與暱稱進行註冊。後端需對密碼進行雜湊安全處理。
- **使用者故事**：
  * 作為一名 **新加入的便便大師**，我希望 **能填寫帳號、密碼與暱稱進行快速註冊**，以便 **建立我在系統中的唯一身份並開始記錄**。

### F-02 戰隊陣營選擇與綁定 (Clan Selection & Binding)
- **功能描述**：註冊時或註冊後，用戶可選擇加入一個戰隊（例如：「高纖陣營」或「多水陣營」）。系統會將該關聯寫入資料庫的戰隊關聯表中。
- **使用者故事**：
  * 作為一名 **注重膳食纖維的用戶**，我希望 **在註冊時能直接選擇加入「高纖陣營」**，以便 **我的每次排便紀錄都能為該戰隊貢獻分數**。

### F-03 後端註冊與寫入路由 (Flask Route: `/register`)
- **功能描述**：Flask 後端提供 `/register` 路由（支援 `GET` 渲染註冊頁面，`POST` 接收註冊表單數據），進行輸入驗證，並在通過後安全寫入 SQLite 資料庫。
- **使用者故事**：
  * 作為一名 **後端開發人員**，我希望 **`/register` 路由能進行嚴格的輸入驗證（如帳號是否重複、密碼長度）**，以便 **確保寫入資料庫的帳號資料都是合法且唯一的**。

### F-04 戰隊分配與關聯寫入路由 (Flask Route: `/join-clan`)
- **功能描述**：Flask 後端提供 `/join-clan` 路由，將目前已登入的用戶 ID 與所選擇的戰隊 ID 寫入對應的資料表中，確保戰隊人數正確更新。
- **使用者故事**：
  * 作為一名 **參賽隊員**，我希望 **系統能自動將我分配到對應戰隊的資料庫欄位中**，以便 **我的個人貢獻與戰隊總分能無縫連動**。

### F-05 會員登入與 Session 保持 (Login & Session Management)
- **功能描述**：已註冊用戶可透過 `/login` 路由登入，系統使用 Flask Session 保持登入狀態，以便在後續功能（如填寫排便紀錄）中自動關聯其個人與戰隊 ID。
- **使用者故事**：
  * 作為一名 **已註冊的便便大師**，我希望 **登入後系統能記住我的狀態**，以便 **我在快速記錄排便時不需重複輸入個人資訊**。

## 3. 非功能需求

### 技術限制
- **開發框架**：使用 Python **Flask** 框架。
- **前端渲染**：使用 **Jinja2 模板** 進行 HTML 網頁渲染，配合 Vanilla CSS 打造精緻的前端介面。
- **資料庫**：使用 **SQLite** 進行本地數據持久化，包含 `users`（用戶表）、`clans`（戰隊表）以及關聯表。

### 效能與安全性考量
- > [!WARNING]
  > **密碼安全**：絕對不能以明文形式將密碼寫入資料庫！必須使用 Werkzeug 的 `generate_password_hash` 進行雜湊加密，驗證時使用 `check_password_hash`。
- **重複驗證**：在寫入帳號前，必須先查詢資料庫是否存在相同 `username`，防止 Unique Constraint 報錯或帳號覆蓋。
- **防呆與欄位驗證**：註冊表單需限制使用者名稱與密碼長度，防範 SQL Injection 以及非法字元。

## 4. MVP 範圍 (Minimum Viable Product)

為了確保核心註冊與戰隊綁定路由能快速上線測試，我們將功能優先級劃分如下：

| 優先級 | 功能名稱 | 具體實現指標 |
| :--- | :--- | :--- |
| 🥇 **Must Have (必須有)** | **1. 會員註冊頁面與後端路由**<br>**2. 密碼 Hash 加密寫入**<br>**3. 戰隊資料庫建立與用戶關聯** | - 完成 `users` 與 `clans` 資料表設計<br>- `/register` 路由實現 `GET` 註冊頁與 `POST` 表單寫入<br>- 註冊時能直接將 `clan_id` 寫入用戶表欄位中。 |
| 🥈 **Should Have (應該有)** | **5. 會員登入功能與 Session 紀錄**<br>**6. 註冊資料庫重複校驗與提示** | - 使用者能正常登入 `/login` 並跳轉至儀表板<br>- 註冊若帳號重複，顯示錯誤訊息而不崩潰。 |
| 🥉 **Nice to Have (加分項)** | **7. 戰隊人數即時統計**<br>**8. 精緻的戰隊介紹與推薦卡片** | - 註冊頁面顯示各戰隊目前人數與介紹<br>- 根據使用者的小測驗推薦適合的戰隊。 |
