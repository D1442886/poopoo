# 拉屎冠軍爭霸賽 產品需求文件 (PRD)

## 1. 專案概述

### 背景與動機
現代人常因飲食不均衡、壓力大導致腸胃問題，然而多數人缺乏定期追蹤排便狀況的習慣。傳統的紀錄方式過於枯燥，難以持之以恆。因此，本專案將日常的「排便紀錄」結合「遊戲化（Gamification）」元素與戰隊競爭機制，將健康管理轉化為有趣的日常挑戰，提升使用者的紀錄意願，進而幫助改善腸胃健康。

### 目標用戶
本系統主要為「關注自身腸胃健康的現代人」所設計，特別是：
- 經常有便秘或腸躁症困擾的大學生與上班族。
- 需要記錄嬰幼兒或長輩排便狀況的照護者。
- 喜歡數據化生活與遊戲化互動的使用者。

### 核心價值主張
- **目標一**：提供直覺的輸入介面，讓使用者能快速記錄排便時間、形狀（參考布里斯托大便分類法）與顏色。 
- **目標二**：將歷史紀錄系統化保存，並提供易於閱讀的清單或月曆檢視。 
- **目標三**：透過數據統計功能，產出個人化的腸胃健康圖表，幫助使用者觀察長期趨勢。

## 2. 功能需求

以下列出系統主要功能及其對應的使用者故事 (User Stories)：

### F-01 會員與戰隊系統
- **功能描述**：帳號註冊與登入。使用者可選擇加入特定的「腸胃戰隊」（如：高纖陣營、多水陣營）。
- **使用者故事**：
  - 作為一名 **新使用者**，我希望 **能註冊帳號並選擇加入一個戰隊**，以便 **開始我的紀錄旅程並為團隊貢獻分數**。
  - 作為一名 **已註冊使用者**，我希望 **能順利登入系統**，以便 **接續先前的紀錄**。

### F-02 首頁個人儀表板
- **功能描述**：顯示「今日是否已紀錄」、連續天數，以及快捷新增按鈕，維持日常使用的清爽感。
- **使用者故事**：
  - 作為一名 **日常使用者**，我希望 **登入後能立刻看到今日狀態與連續紀錄天數**，以便 **獲得成就感並被提醒是否該去紀錄**。
  - 作為一名 **趕時間的使用者**，我希望 **首頁有顯眼的新增按鈕**，以便 **能一鍵快速進入紀錄表單**。

### F-03 快速排便紀錄表單
- **功能描述**：核心日常功能，透過布里斯托圖示點選大便形狀與顏色。系統會在提交後跳出「本次獲得 X 積分」的提示。
- **使用者故事**：
  - 作為一名 **需要紀錄排便的使用者**，我希望 **能透過視覺化的圖示（布里斯托分類法）點選形狀和顏色**，以便 **直覺且快速地完成紀錄，不需手動輸入過多文字**。
  - 作為一名 **喜歡遊戲化回饋的使用者**，我希望 **送出紀錄後能看到獲得的積分提示**，以便 **知道我這次「表現」得如何**。

### F-04 歷史月曆與紀錄管理
- **功能描述**：將歷史資料轉化為月曆視圖，哪天有健康排便一目了然，並可修改或刪除紀錄。
- **使用者故事**：
  - 作為一名 **關注長期腸胃狀態的使用者**，我希望 **能以月曆形式查看過往的排便紀錄**，以便 **一眼看出這個月的排便頻率與健康狀況**。
  - 作為一名 **可能不小心填錯的使用者**，我希望 **能編輯或刪除過去的紀錄**，以便 **維持數據的正確性**。

### F-05 個人數據與戰力分析
- **功能描述**：將個人的排便頻率、健康便便比例繪製成統計圖表（如圓餅圖或雷達圖）。
- **使用者故事**：
  - 作為一名 **想了解自身腸胃健康趨勢的使用者**，我希望 **能看到健康便便比例與頻率的圖表分析**，以便 **評估近期的飲食與生活習慣是否需要調整**。

### F-06 戰隊積分與資源核算
- **功能描述**：後端自動將使用者的排便健康度（如：香蕉狀分數最高）與連續紀錄天數，換算成所屬戰隊的總積分。
- **使用者故事**：
  - 作為一名 **戰隊成員**，我希望 **系統能根據我的「便便健康度」與「連續天數」給予獎勵積分**，以便 **更有動力維持健康的排便習慣**。

### F-07 全服排行榜與戰報
- **功能描述**：顯示各戰隊的當前總積分排名，以及本週貢獻度最高的「個人 MVP」，激發團隊榮譽感。
- **使用者故事**：
  - 作為一名 **具備好勝心的使用者**，我希望 **能看到各戰隊的積分排行榜以及個人 MVP**，以便 **享受與其他玩家競爭的樂趣並為戰隊爭取榮耀**。

## 3. 非功能需求

### 技術限制
- 前端：使用 HTML / CSS / JavaScript 搭配 **Jinja2 模板引擎** 進行頁面渲染。
- 後端：使用 **Python Flask** 框架處理 API 與頁面路由。
- 資料庫：使用 **SQLite** 進行資料儲存，以簡化本地端開發與部署。

### 效能與體驗考量
- **響應式設計 (RWD)**：考量使用者大多會在廁所使用手機進行紀錄，系統需高度支援行動裝置版面 (Mobile-first)。
- **快速載入**：首頁與紀錄表單應能快速呈現，減少使用者等待時間。
- **防呆機制**：日期預設為當下，防止輸入未來時間；顏色與形狀需為必填選項。

### 安全考量
- 使用者密碼需經過雜湊 (Hash) 處理後再存入資料庫。
- 確保個人隱私資料（排便習慣與紀錄）的存取權限控管，使用者僅能查看與修改自己的紀錄。

| 優先級 | 功能名稱 | 備註 |
| --- | --- | --- |
| **Must Have (必須有)** | F-01 會員註冊與登入<br>F-03 快速排便紀錄表單<br>F-04 歷史清單（先實作清單，月曆為加分項） | 滿足最基本的紀錄與個人資料存取功能。 |

| **Nice to Have (加分項)** | F-04 歷史月曆視圖<br>F-05 個人數據與戰力分析圖表<br>F-07 個人 MVP 展示 | 豐富視覺化圖表與進階排行功能，視開發時間充裕度決定是否納入。 |
